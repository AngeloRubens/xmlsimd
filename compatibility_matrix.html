Integration Details

Jakarta XML Binding Provider

The org.simdxml:simdxml-jaxb-provider artifact is a dependency-only bridge that registers org.simdxml.jaxb.SimdJaxbContextFactory as a jakarta.xml.bind.JAXBContextFactory. Existing application code remains unchanged:

JAXBContext context = JAXBContext.newInstance(Message.class);
Marshaller marshaller = context.createMarshaller();
Unmarshaller unmarshaller = context.createUnmarshaller();

When the provider jar and simdxml-java are selected ahead of another JAXB implementation, these objects are backed by simdxml.

Java EE 8 / Javax XML Binding Provider

For Java EE 8 runtimes use org.simdxml:simdxml-jaxb-javax-provider together with org.simdxml:simdxml-core-java8. Application endpoint and model code continues to call the normal javax.xml.bind API. The bridge includes both the JAXB 2.3 factory service and the legacy Java 8 provider service, is compiled as Java 8 bytecode.

Server Smoke Tests

The project includes reproducible server smoke tests for Open Liberty and Tomcat:

  • Open Liberty: The openliberty-it Maven profile resolves a pinned Open Liberty kernel, installs only servlet-4.0 and jaxb-2.2, starts one server JVM, calls the servlet over HTTP, and verifies provider selection and round-trip correctness.
  • Tomcat: The tomcat-it profile downloads only Tomcat Embedded 9.0.120, deploys the same packaged WAR on an ephemeral port, and verifies that the selected provider was loaded from the WAR's own WEB-INF/lib.
  • Quarkus: The quarkus-it profile uses Quarkus 3.38.1 plus its stable JAXB extension and verifies the Jakarta simdxml provider from inside a running Quarkus endpoint.

Notes

All integration claims are at the dependency level: application source remains unchanged and only the provider dependency, archive contents, or server configuration is adjusted.

Cold-path JAXB behavior (such as generateSchema()) is resolved once per context and cached. Set -Dorg.simdxml.jaxb.coldPathFactory= when a container requires an explicit vendor factory; otherwise JAXB RI and EclipseLink MOXy are detected through the thread context classloader.

The JAXBElement wrappers created by CXF/JAX-WS are marshalled natively by simdxml; only schema generation and other genuinely rare compatibility operations use the delegate.
